1–2) المقدمة والرؤية

مرآتي الرقمية منصة عربية أولاً (RTL) تساعد المتضررين من الجرائم الرقمية على التصرف بهدوء: مساعد حوادث يصنّف الواقعة ويعطي خطة مرتبة، إبلاغ آمن عن الابتزاز بمتابعة مشفرة بلا حساب ولا هوية، نظام أدلة رقمية يحفظ البيانات الوصفية دون استقبال أي ملفات، أكاديمية توعية، أدوات خصوصية تعمل محلياً، وسجل لكل الدول العربية الـ22 بحالات تحقق صادقة. الرؤية: بنية تحتية عربية للمساعدة والإحالة الآمنة والتعاون المؤسسي — تبدأ بإثبات جودة الخدمة في نطاق تجريبي، ثم تتوسع باتفاقات حقيقية.

        │ fetch نفس النطاق + connect-src api.pwnedpasswords.com

  ├─ الأمن: CSP/HSTS، rate limiting، zod، سجلات بلا محتوى، redact()
  ├─ /api/report /api/cases/* → نظام القضايا (scrypt + MR-)

تقنيات محفوظة: React 18، Vite، Express، TypeScript، SQLite. لا PostgreSQL/Redis حالياً — الانتقال مخطط (خطة DEPLOYMENT_GUIDE) ولا يكسر التوافق لأن كل الوصول للبيانات عبر طبقة Store واحدة.

8) شرح كل وظيفة (ملخص)

المساعد: تطبيع عربي (همزات/تشكيل/تاء) → مطابقة إشارات 19 دليلاً → كشف غموض بسؤال فارق → سؤال واحد للمضغوط/اثنان لغيره → استعجال رباعي بسبب معلن (خطر جسدي/قاصر = طارئة فوراً) → خطة ثلاث مراحل، كل خطوة: ماذا/لماذا/كيف تتأكد/إن لم ينجح → خطط مفقود-التحكم تتصدر. الإبلاغ الآمن: بلاغ بلا حساب/اسم، لا يُرسل لأي جهة تلقائياً. المتابعة: رقم+رمز فقط، بلا استرجاع للرمز المفقود (معلن). الأدلة: بيانات وصفية فقط + بصمة يحسبها المستخدم محلياً — منع صريح لرفع أي ملف، وخاصة المحتوى الحميم أو المتعلق بقاصرين (يوجَّه لقنوات Take It Down/CyberTipline في المساعد). الأدوات: كلمات المرور محلية، تسريبات البريد بالبصمة عبر بروكسي بلا تسجيل، الروابط تحليل بنيوي دون زيارة.

11) واجهات الجهات الحكومية

غير مفعّلة عمداً. التصميم الكامل (أدوار RBAC الثمانية، OAuth2 Client Credentials، MFA، Webhooks موقعة، Idempotency، تدوير مفاتيح، مسار الشراكة العشري) في GOVERNMENT_PARTNERSHIP_GUIDE.md. التنفيذ يبدأ فقط مع أول جهة حقيقية بعد اتفاق موقّع واختبار ببيانات مصنّعة.

12) نظام الدول العربية

سجل 22 دولة بخمس مناطق، لكل دولة صفحة مستقلة. حالات التحقق الخمس مطبقة؛ VERIFIED يحتاج فحصاً فعلياً بتاريخ ومصدر (الاختبار الآلي يمنع VERIFIED بلا تاريخ). البحرين مفحوصة فعلاً (2026-10-26)، والبقية PENDING_REVIEW بصدق — جدول كامل في ARAB_COUNTRIES_DIRECTORY.md. القوانين لا تُعامل كقانون واحد، ولا تُقدَّم استشارات قانونية.

13) نظام الإبلاغ عن الابتزاز

معالج ثلاث خطوات: نوع الحادثة (19 + أخرى) → وضع الضحية (مستمرة/تهديد نشر/قاصر/خطر جسدي) → دولة اختيارية + ملخص حر اختياري + موافقة صريحة على التخزين. إن وُجد قاصر أو خطر جسدي: إشعار فوري يوجه للطوارئ (البلاغ الإلكتروني لا يصل للطوارئ — معلن). لا اسم ولا هاتف ولا هوية. النتيجة: رقم MR- + رمز متابعة يُعرض مرة واحدة (يُخزن scrypt — فقدانه نهائي، معلن مسبقاً). البلاغ لا يُرسل لأي جهة — الإحالة مستقبلية بموافقة منفصلة.

14) نظام الأدلة الرقمية

فلسفة: تنظيم التوثيق دون لمس المحتوى الحساس. المستخدم يسجل لكل دليل: النوع (رسالة/حساب/رابط/مالية/أخرى)، المنصة، وقت الحدث ومنطقته، وصفاً ≤800 حرف، وبصمة SHA-256 اختيارية يحسبها بنفسه محلياً (مثال موثق بالصفحة: certutil على ويندوز) — الملف لا يغادر جهازه أبداً. سجل حيازة يسجل الإنشاء وكل اطلاع. تقرير قابل للطباعة/PDF من المتصفح. المحظور في الكود والتصميم: رفع أي ملف (خاصة حميم/قاصرين)، معالجة أو تصنيف صور، والدعم: SHA-256 أداة تنظيم لا إثبات أصالة قاطع (معلن). حزمة التصدير المشفرة AES-256-GCM متبقية (PROJECT_PROGRESS.md).

15) نظام الموافقات

موافقة تخزين إلزامية (لا تُنشأ قضية بدونها — مُختبر) بعد إشعار يفصّل ما يُخزن وما لا يُخزن. سحب الموافقة = حذف نهائي ذاتي فوري. الإحالة المستقبلية = موافقة منفصلة محددة النطاق حرفياً (لم تُبنَ بعد عمداً حتى أول جهة رسمية).

16) الصلاحيات

حالياً: دورا admin/editor لمشرفي المحتوى بجلسات HMAC (8 ساعات، httpOnly، SameSite=Strict) + CSRF مزدوج. القضايا: مالكها الوحيد عبر رقم+رمز — لا يرى المشرف المحتوى عبر اللوحة (إحصاءات مجمعة فقط). الأدوار المؤسسية الثمانية (Super Admin → Content Editor) مصممة في دليل الشراكة وتُنفذ مع أول شريك.

17) التشفير

  • رموز متابعة القضايا: scrypt (ملح عشوائي، مقارنة زمنية ثابتة) — النص الصريح لا يُخزن
  • كلمات مرور المشرفين: scrypt
  • الجلسات: HMAC-SHA256 موقعة
  • النقل: HTTPS/HSTS إلزامي إنتاجاً — ولا نسميه تشفيراً طرفياً، ولا نعد بسرية مطلقة
  • قيد معلن: بيانات القضايا غير مشفرة-at-rest بعد — الخطة: AES-256-GCM بمفتاح منفصل عن القاعدة/KMS، بحيث لا يملك مشرف واحد فك كل شيء (موثق بجدول في PRIVACY_AND_DATA_RETENTION.md). حد الإطلاق الأدنى: تشفير قرص الاستضافة.

18) سياسة الخصوصية

معروضة للمستخدم في /privacy وبصيغة مؤسسية في PRIVACY_AND_DATA_RETENTION.md: فصل طبقة المحادثة (لا تخزين) عن طبقة القضايا (أدنى حد + موافقة + حذف ذاتي)، ما لا نجمعه أصلاً (هوية/IP مرتبط/ملفات)، وحدود لا تُخترق (لا إرسال للنماذج، لا تدريب على المحادثات، لا تتبع ولا بيع).

19) حماية المنصة

التفصيل مع أدلة الاختبارات في SECURITY_AUDIT_REPORT.md: SSRF (9 اختبارات)، IDOR على القضايا، Brute Force (رمز ~100 بت + حدود معدل)، CSRF، جلسات، SQLi (استعلامات معلمية)، XSS (CSP بلا سكربت خارجي)، Clickjacking، Prompt Injection (المجلوب بيانات بعد stripHtml، والمحرك حتمي لا ينفذ تعليمات)، تسريب أسرار (redact + بلا محتوى مستخدمين في السجلات). متبقٍ قبل الإطلاق الحقيقي: مراجعة OWASP ASVS مستقلة، WAF، مراقبة مركزية، تشفير-at-rest.

26) ربط جهة حكومية عملياً

المسار الكامل بعشر خطوات (طلب → تحقق هوية عبر قنوات الجهة المنشورة → تحقق اختصاص → مراجعة قانونية وأمنية → اتفاق موقّع → قناة تكامل → اختبار ببيانات مصنّعة → اعتماد → مراقبة → مراجعة دورية) مع مثال تدفق الإحالة وقواعد صلبة (لا وصول عبر الدول، لا بيانات خارج نص الموافقة، إلغاء فوري) — كل ذلك في GOVERNMENT_PARTNERSHIP_GUIDE.md. ابدأ بجهة تجريبية واحدة لا 22 تكاملاً دفعة واحدة.

27) طلب شراكة من منظمة

نفس مسار العشر خطوات — حالة الطلب مستقلة، ولا تظهر المنظمة كشريكة في أي مكان (مركز الشفافية يعرض activePartnerships=0) قبل الاعتماد الرسمي. صفحة «انضم إلى الشبكة» العامة ضمن المتبقي (PROJECT_PROGRESS.md).

28) كيفية إضافة دولة جديدة

أضف كائناً في shared/content/countries.ts (code/nameAr/nameEn/region) — الصفحة والـAPI يُشتقان تلقائياً. املأ الجهات فقط من مصادر رسمية فحصتَها بنفسك؛ VERIFIED بلا تاريخ يفشل الاختبار الآلي. التفاصيل في ARAB_COUNTRIES_DIRECTORY.md.

29) كيفية إضافة جهة أمنية

ضمن كائن الدولة: cert/cybercrime/childProtection بالاسم والرابط والحالة والمصدر. للتحديث الدوري: راجع الرابط، عدّل verifiedAt وlastReviewed، أو غيّر الحالة لOUTDATED/DISPUTED عند التوقف/التعارض.

30) كيفية إضافة درس جديد

قالب جاهز للنسخ في GUIDE.md (القسم 4): id فريد، track، objective، sections، أمثلة آمن/مزيف، quiz بتفسيرات، checklist، minutes، order — ثم npm test && build. يظهر تلقائياً في مساره مع الاختبار.

31) كيفية إضافة API جديدة

النمط المعمول به: مخطط zod للمدخلات → rateLimit → منطق عبر Store → استجابة JSON بلا بيانات شخصية زائدة → اختبار في tests/ → typecheck → build. راجع ملفات server/app.ts (نماذج: report/cases) وtests/cases.test.ts كنموذج.

34) المخاطر والقيود المتبقية (بصدق)

  • حرج قبل الإطلاق لا مراجعة أمنية/اختراق مستقلة — مطلوبة قبل استقبال قضايا حقيقية
  • مهم بيانات القضايا غير مشفرة-at-rest (خطة AES-256-GCM + KMS موثقة)؛ حد الإطلاق الأدنى: تشفير قرص الاستضافة
  • مهم 21 دولة جهاتها قيد التحقق — لا تُعرض كجهات مؤكدة ولا تُختلق بياناتها
  • مهم بوابة الجهات الحكومية تصميم فقط — عمداً حتى أول اتفاق
  • متبقي حد المعدل في الذاكرة (يلزم Redis للتوسع) · لا WAF/مراقبة مركزية · حزمة تصدير أدلة مشفرة · i18n إنجليزي · نظام إنذار مبكر · مسار حماية النساء والأطفال كصفحة مخصصة · 5 أدوات جديدة
  • حدها التصميم رمز المتابعة المفقود غير قابل للاسترجاع — معلن قبل الإنشاء

35) خطة التطوير المستقبلية

  1. التحقق الميداني من مصادر 21 دولة (بحث وتوثيق — يرفع قيمة الإحالة المستقبلية)
  2. مسار حماية النساء والأطفال كواجهة مخصصة (الإرشادات موجودة؛ التجميع واللغة)
  3. تشفير القضايا AES-256-GCM + إدارة مفتاح منفصلة
  4. أدوات: حاسبة بصمة محلية بالسحب والإفلات، فاحص QR، فاحص ترويسات، سمعة نطاق
  5. حزمة تصدير الأدلة المشفرة + واجهة Integrations
  6. بوابة الشراكات مع أول جهة تجريبية (OIDC، Webhooks موقعة، Idempotency)
  7. i18n + الإنذار المبكر المجمّع + خطة الاحتفاظ الآلية (12 شهراً)
  8. مراجعة OWASP ASVS مستقلة ثم إطلاق تجريبي محدود بدولة واحدة
الخلاصة الصادقة: المنصة تعمل فعلياً وتُختبر (103 اختباراً + تحقق حي)، ووظائف الحماية الأساسية (الإبلاغ الآمن، القضايا، الأدلة، الدول، الشفافية) مكتملة النواة. ما هو غير مكتمل موثق بالاسم أعلاه — ولا يوجد في المنصة جهة وهمية أو رابط مختلق أو وظيفة شكلية معلنة كعاملة أو مفتاح مكشوف.
